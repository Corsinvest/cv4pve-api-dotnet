## Why

An application that manages Proxmox VE (a customer portal, a scheduled job, a monitoring or billing
tool) has to speak its REST API: tickets and tokens, paths, parameters, JSON, tasks that end later.
Written by hand it is a layer of HTTP code to build and to keep up with every Proxmox VE release.

cv4pve-api-dotnet is that layer, generated from the API itself. The calls follow the tree of the API,
so the [Proxmox VE API viewer](https://pve.proxmox.com/pve-docs/api-viewer/) is also the reference of
the client, and IntelliSense shows the same descriptions while you type.

```csharp
using Corsinvest.ProxmoxVE.Api;

var client = new PveClient("pve01")
{
    ApiToken = "automation@pve!app=aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee"
};

// GET /nodes/{node}/qemu/{vmid}/status/current
var result = await client.Nodes["pve01"].Qemu[100].Status.Current.VmStatus();

Console.WriteLine(result.IsSuccessStatusCode
                    ? $"VM {result.Response.data.vmid} is {result.Response.data.status}"
                    : $"{(int)result.StatusCode} {result.ReasonPhrase}");
```

## In your application, API only

The client runs where .NET 8, 9 or 10 runs (Windows, Linux, macOS, a container, a CI runner) and talks
only to the Proxmox VE REST API on port 8006. Nothing is installed on the nodes and no SSH is needed.
What an application can do is what its API token or user is allowed to do: give it a token with just
the privileges it needs, see [Permissions](/cv4pve-api-dotnet/permissions/).

## Where it fits

The cv4pve suite follows the Unix philosophy: each tool does one thing and does it well. This library
is what the .NET tools of the suite are built on, among them
[cv4pve-cli](https://corsinvest.github.io/cv4pve-cli/),
[cv4pve-autosnap](https://corsinvest.github.io/cv4pve-autosnap/),
[cv4pve-diag](https://corsinvest.github.io/cv4pve-diag/) and
[cv4pve-report](https://corsinvest.github.io/cv4pve-report/): use it to build your own. If a ready tool
already does the job, use the tool. For scripts rather than applications, the same API is available
from PowerShell with [cv4pve-api-powershell](https://corsinvest.github.io/cv4pve-api-powershell/).
